The Maths, Visually

Hypervectors Explained

Everything my maps remember lives in one fixed-size vector. Think of it as a strip of tape holding thousands of tiny clock hands, each frozen at some angle. Three operations on those angles are the whole algebra — and every widget below runs the honest construction live in your browser, not a mock-up.

⊗ bind = add the angles — attach a what to a where + bundle = superpose — many memories on one tape ⊘ unbind = subtract the angles — ask a question

1 · A Place Is a Pattern of Clock Hands

Drag the sliders to move a point around a room. Each dial below is one dimension of the vector: moving in x spins every hand at its own fixed rate (and y at another) — that is fractional power encoding. No two places share a pattern, yet nearby places nearly do.

What you're seeing. The bright blob is similarity: the mean of cos(phase difference) across all dimensions. It falls to half height by ≈0.3ℓ — which is exactly why every "where is it?" answer later on this page is a blob, not a lit pixel. And because S(a) ⊗ S(b) = S(a+b) exactly, moving a whole memory is a single elementwise multiply — no decoding, no grid, no approximation.

2 · Binding Attaches What to Where

Bind an object's identity to a place and the result resembles neither — it looks like noise. Like stacking two tinted transparencies: unreadable, but nothing is lost. Hold the right complementary filter (unbind key) up to it and the place snaps back into focus. The wrong key returns pure static.

3 · One Vector Holds Many Memories — Until Crosstalk Wins

Bundle k (object ⊗ place) memories onto one tape — the tape never gets longer, the recordings just get noisier. Unbind object #0 and check its place against 40 candidates: the correct one carries signal ≈ 1/k, the rest are crosstalk. The margin between them is predicted by √(2D/k) — dimensionality buys capacity, and you can watch it run out.

From the ICRA Talk

SLAM That Thinks in Vectors

A robot in a new building must answer "where am I?" and "where is everything?" at the same time. Counting your steps in the dark — path integration — inevitably drifts. The fix: every landmark the robot sees is bound into the same vector memory you just met above, and recognising one later lets the algebra pull the position estimate back. Below, that loop runs live — with a genuine FHRR memory doing the corrections, crosstalk and all.

Live: Drift vs. The Vector Map

One agent, three position estimates. Grey is the truth. Amber integrates noisy velocity and slowly drifts away. Cyan integrates the same noisy velocity — but each landmark sighting is bound into a real FHRR memory, and each re-sighting is decoded back out of it (unbind → correlate → peak) to correct the estimate.

What you're seeing. This is the SSP-SLAM loop in miniature: the full system (Dumont et al., Frontiers in Neuroscience 2023) runs the same algebra in spiking neurons — the position vector lives in a population of velocity-controlled oscillators with attractor dynamics, and the map is an associative memory learned online with PES. Turn corrections off and watch amber and cyan drift together; turn them back on and the next landmark sighting snaps cyan home. The decode is honest, so with a small D the correction itself is noisy — that's crosstalk, not a bug.

Why the Brain Appears — Grid Cells Fall Out of the Maths

Build the position code from hexagonally arranged frequency components (three plane waves at 120°, as in HexagonalSSPSpace) and the similarity map of a single module is a hexagonal firing lattice — the signature of entorhinal grid cells. Stack modules at different scales and rotations and the lattice interference collapses into a single bump: a place cell. Slide to add modules.

grid modules combined1 module

One module says "you are at one of these lattice points" — periodic, ambiguous. Six modules at co-prime scales agree at exactly one place. That is the residue-number-system trick the mammalian brain appears to use, and it is why the path integrator can be built from populations of oscillating grid cells.

Then ask it questions: where are the chairs? unbinds CHAIR and correlates the residue against every position (the heatmap is the raw answer, crosstalk included). Watch the trade-off happen. The memory readout above never grows — ten objects or a hundred, it is the same D numbers. Add many objects and the Where is…? heatmap gets speckly (crosstalk), exactly as the capacity widget predicts with √(2D/k). Drop D to 256 to make it fail sooner; raise ℓ and blobs widen but neighbouring objects start to blur together. This is the engineering dial the real system lives on.
